# Milestone 4 Reciprocal Rank Fusion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Fuse dense and sparse candidate rankings into one deterministic list without duplicate chunks.

**Architecture:** A pure Python function consumes Milestone 3 HybridCandidates. It assigns each chunk a reciprocal rank contribution per channel and returns one FusedChunk per chunk_id, retaining source metadata and channel provenance.

**Tech Stack:** Python 3.12, pytest, Ruff; no new database or model dependency.

**Spec:** docs/plans/specs/2026-11-01-rag-retrieval-m2-m8-design.md

## Global Constraints

- RRF score is sum of 1 / (60 + one-based rank) for each channel containing a chunk.
- Deduplicate by chunk_id, not by content or document_id; preserve different chunks from the same document.
- Input lists are already scoped by Milestones 2–3; fusion must not broaden the scope.
- Equal scores sort by chunk_id for deterministic output. Never compare dense cosine distance to sparse score directly.
- One task, one tested commit.

## Review Focus

- Same chunk in both channels appears once and receives both contributions (test_rrf_deduplicates_chunk_id).
- Two chunks with identical text but different IDs stay separate (test_rrf_keeps_distinct_chunks).
- Empty one/both channels produce the expected list (test_rrf_empty_channels).
- Duplicate ID within one channel does not earn a second contribution (test_rrf_repeated_id_within_channel).
- Equal fused scores use stable chunk-ID order (test_rrf_tie_order).
